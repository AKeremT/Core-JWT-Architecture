🧠 Sektörel Mimari Kararlar ve Gerekçeleri

1. Sıfır Veritabanı Sorgusu (Zero-DB Hit) ile Filtreleme

Neden? Tutorial'larda her HTTP isteğinde veritabanına loadUserByUsername sorgusu atılır. Biz token claim'lerine rolleri gömdük ve filtrede tek bir parse ile SecurityContext kurduk. Bu sayede veritabanına her istekte `SELECT` atılmasını önleyerek gerçek bir stateless mikroservis performansı sağladık.

2. Composition over Inheritance (CustomUserDetails Ayrımı)

Neden? User JPA entity'sine doğrudan implements UserDetails demedik. Domain entity'mizi framework bağımlılığından korumak için ayrı bir CustomUserDetails wrapper sınıfı yazdık.

3. Refresh Token Rotation (RTR - OWASP Standardı)

Neden? Saf access token'lar süre bitene kadar iptal edilemez. Refresh token'ı veritabanında opaque (UUID) olarak tuttuk ve her yenilemede eskisini silip yepyeni bir refresh token verdik. Böylece token hırsızlığı riski minimuma indi.

4. JPA @EntityGraph Optimizasyonu

Neden? RefreshToken ile User ilişkisini güvenli olması için LAZY yaptık. Ancak token sorgularken @EntityGraph(attributePaths = {"user"}) kullanarak tek bir SQL JOIN ile kullanıcıyı çektik; böylece hem LazyInitializationException'ı hem de N+1 problemini çözdük.

5. REST API Uyumlu JSON Hata Yönetimi

Neden? Spring Security varsayılan olarak HTML yönlendirmesi yapar. Biz AuthenticationEntryPoint (401), AccessDeniedHandler (403), BadCredentialsException (401) ve TokenNotFoundException (401) ile istemciye daima standart JSON hata dökümleri döndük.

🔄 Sistemin Uçtan Uca Akışı (Step-by-Step)

1. Kullanıcı Kaydı (Registration Flow)

İstemci POST /api/auth/register isteği atar.

RegisterRequest(username, password, email)
  ↳ UserRepository: Kullanıcı adı var mı kontrolü (varsa 409 Conflict)
  ↳ BCryptPasswordEncoder: Şifre hash'lenir
  ↳ User & Role: Varsayılan Role.USER atanır ve DB'ye kaydedilir
  ↳ JwtService: 15 dakikalık Access Token üretilir
  ↳ RefreshTokenService: 7 günlük UUID Refresh Token üretilir ve DB'ye yazılır
  ↳ AuthResponse: { accessToken, refreshToken } dönülür.

2. Kullanıcı Girişi (Login Flow)

İstemci POST /api/auth/login isteği atar.

LoginRequest(username, password)
  ↳ AuthenticationManager: kimlik doğrulamayı başlatır
    ↳ CustomUserDetailsService: DB'den kullanıcıyı çeker ve CustomUserDetails döner
    ↳ PasswordEncoder: Hash eşleşmesini kontrol eder (yanlışsa 401 BadCredentials)
  ↳ Objects.requireNonNull(auth.getPrincipal()): Null-safety garantiye alınır
  ↳ Token Üretimi: Yeni Access Token ve Kullanıcının eski token'ı silinip yeni Refresh Token verilir.

3. Korumalı Kaynaklara İstek (Zero-DB Hit Authentication)

İstemci GET /api/private/user isteği atar ve Header ekler: Authorization: Bearer <accessToken>.

JwtAuthenticationFilter:
  ↳ Header "Bearer " ile başlıyor mu?
  ↳ jwtService.extractAllClaims(token): Tek parse ile imza ve süre doğrulanır
  ↳ Claims'ten Okuma: Subject (username) ve "roles" claim'i alınır
  ↳ DB'ye HİÇ GİTMEDEN: User.withUsername(...).authorities(...) ile UserDetails üretilir
  ↳ SecurityContextHolder: Authentication nesnesi context'e konur
  ↳ @PreAuthorize("hasAnyRole('USER', 'ADMIN')"): Rol doğrulanır ve 200 OK yanıt döner!

4. Token Yenileme (Refresh Token Rotation - RTR Flow)

Access Token süresi (15 dk) bittiğinde istemci POST /api/auth/refresh isteği atar.

RefreshTokenRequest(token: "<UUID>")
  ↳ RefreshTokenRepository: @EntityGraph ile User ile birlikte tek SQL JOIN ile bulunur
  ↳ verifyExpiration(): Süresi dolmuş mu veya revoked mu? (Dolmuşsa silinir, 401 fırlar)
  ↳ Token Rotation (Kritik): Eski refresh token DB'den silinir (deleteByUser)
  ↳ Yeni Çift: Yeni Access Token + Yepyeni Refresh Token üretilir
  ↳ AuthResponse: { accessToken: "yeni...", refreshToken: "yepyeni..." } dönülür.

Metot URL Yetki Seviyesi Hata Durumunda HTTP Kodu

POST /api/auth/login Herkese Açık (permitAll) 401 Unauthorized (Hatalı şifre/kullanıcı)
POST /api/auth/refresh Herkese Açık (permitAll) 401 Unauthorized (Geçersiz/Süresi bitmiş token)
GET /api/private Authenticated (Token Sahibi) 401 Unauthorized (Token yoksa/hatalıysa)
GET /api/private/user USER veya ADMIN 401 (Token yoksa) / 403 (Rol uymuyorsa)
GET /api/private/admin Sadece ADMIN 403 Forbidden (USER rolü erişmeye kalkarsa)
